⭐ 可视化内容管理系统设计文档

1. 项目背景与目标

1.1 背景

当前 Hugo 静态网站项目托管在 Netlify，源代码在 GitHub，网站内容（供应商信息、产品信息、新闻、展会、案例）完全依赖本地文件编辑和 Git 提交。

需求市场版块需要发布方管理需求、查看报价明细，供应商可针对需求发布报价。

图片、附件目前存放在项目结构中，新增内容必须修改文件夹结构并提交 Git，操作复杂、非直观，无法给非技术人员使用。


1.2 目标

构建一个 可视化、直观、后台操作即生效的内容管理系统（CMS），实现供应商/产品/新闻/展会/案例/需求市场统一管理。

后台操作可实时更新前端数据，无需修改文件或提交 Git。

图片、附件统一存储到 Cloudflare R2 并生成 CDN URL，前端静态站直接引用。

提供可扩展的数据模型，方便未来增加模块或业务功能。

后台访问控制可通过 Cloudflare Access 实现。

保持 Hugo 静态站 SEO 优势和快速访问性能。



---

2. 设计理念

2.1 模块化管理

每类内容独立模块：供应商、产品、新闻、展会、案例、需求市场

每个模块包含：

列表视图：显示所有条目、状态、操作

编辑/新增表单：支持文本、富文本、图片上传、关联选择

删除操作



2.2 数据驱动

所有内容存储在 Cloudflare D1 数据库（轻量 SQL）

图片、附件通过 R2 存储并生成公开 URL

Worker API 提供统一的 CRUD 接口，前端与后台均通过 API 获取和更新数据


2.3 前端静态 + 动态数据

Hugo 页面仍保持静态构建

内容通过 Worker API fetch 动态加载

可选：Hugo 构建时通过 getJSON 拉取数据，实现静态渲染


2.4 安全与权限

后台统一通过 Cloudflare Access 控制登录权限

需求市场可设置审核开关，支持审核或免审核

后台操作记录可通过 Worker 内部日志实现，便于审计


2.5 可扩展性与维护性

新业务模块只需在 D1 数据库建表、Worker API 增加接口、后台增加表单即可

前端 Hugo 页面通过 fetch 对接 API，无需修改构建流程

全部系统免费，利用 Cloudflare 免费额度（Pages、Workers、D1、R2）

3. 实施原理

3.1 架构概览

前端 Hugo 网站
       │
       │ fetch API / getJSON
       ▼
Cloudflare Workers API
       │
       ├── D1 数据库（存储供应商/产品/新闻/展会/案例/需求市场数据）
       └── R2 图片存储（图片、附件）
       
Cloudflare Pages 后台管理界面（/admin/）
       │
       ├── HTML + CSS + JS
       └── 调用 Workers API 实现 CRUD 和图片上传
       
Cloudflare Access
       │
       └── 控制后台登录权限

3.2 数据流原理

1. 后台新增/编辑内容

用户在 /admin/ 页面填写表单

JS 调用 Worker API → 写入 D1 / 上传图片到 R2

返回数据 JSON → 页面更新显示



2. 前端显示内容

Hugo 页面加载时通过 fetch /api/模块名 获取 JSON

JS 渲染 HTML / 卡片 / 列表

图片通过 R2 CDN URL 显示



3. 需求市场管理

供应商提交报价 → Worker API 写入 D1

平台可选择开启/关闭审核开关

审核通过后前端显示数据



4. 权限与安全

Cloudflare Access 保护 /admin/

前台可根据业务需求控制供应商 / 发布方 / 公开访问权限

4. 实施步骤

4.1 数据库设计

建立 D1 表，覆盖所有模块：

suppliers、products、news、events、cases、demands

每个表含通用字段：ID、标题/名称、描述、图片 URL、创建时间、状态

关联字段：产品关联供应商、案例关联产品、需求关联报价



4.2 Worker API 实现

CRUD 接口：GET / POST / PUT / DELETE

图片上传签名 URL 生成接口

审核功能接口（需求市场 / 报价开关）

返回标准 JSON，前端直接消费


4.3 后台管理界面

页面 HTML + CSS + JS

左侧模块列表，右侧详情/操作表单

拖拽上传图片，多图预览

审核按钮、开关按钮

调用 API 实现所有操作


4.4 Hugo 前端展示

页面模板 fetch API 数据

渲染列表/卡片/详情

图片直接使用 R2 CDN URL

需求市场列表可根据状态筛选（审核通过/未通过）


4.5 权限配置

Cloudflare Access 设置

后台登录账号/组管理

可针对不同角色开放不同模块


4.6 发布与维护

后台操作实时生效，无需 Git 提交

Hugo 构建仍可保留，前端静态页面 SEO 优势

新模块扩展时只需增加 D1 表 + Worker API + 后台表单

图片存储统一在 R2，无需占用项目体积
