# 可视化后台执行方案 (2.0 运营增强版)

这份文档基于原参考方案，结合**“平台统一管理、重SEO推广、长期运营”**的核心战略进行了深度优化。本方案不仅仅是一个技术实现指南，更是一个**内容运营与SEO中心**的构建蓝图。

---

## 1. 核心设计理念：从“管理”到“运营”

### 1.1 战略重心转移
*   **现状**：原有设计偏向于“增删改查”的功能实现。
*   **升级目标**：
    *   **平台主导权**：供应商体系、产品发布、案例展示由平台统一管控，确保内容质量与风格统一。
    *   **SEO 优先**：所有内容模块（产品、案例、资讯）必须内置 SEO 优化字段（Slug, Meta Tags, Structured Data），为长期流量增长打底。
    *   **资源集约化**：建立统一的**数字资产管理 (DAM)** 模块，集中管理图片、PDF 手册、技术文档，避免文件散乱。

### 1.2 需求市场：运营化改造
需求市场不仅是信息发布地，更是**线索撮合中心**。新方案将增加：
*   **运营干预能力**：管理员可对优质需求进行“置顶”、“推荐”、“加急”，人工提升曝光。
*   **撮合辅助**：后台自动根据需求关键词匹配潜在供应商，辅助管理员进行精准推送。
*   **信任建设**：前端展示更细致的状态流转（如“对接中”、“平台已核验”），提升访客信任度。

---

## 2. 数据库设计升级 (D1 Schema)

在原有基础上，**全线增加 SEO 与运营字段**，并新增资源管理表。

### 2.1 通用 SEO 字段标准
所有公开内容表（`products`, `news`, `cases`, `exhibitions`）均需包含以下字段：
*   `slug` (TEXT UNIQUE): URL 友好的短链接标识（如 `vis-t2810-endoscope`）。
*   `seo_title` (TEXT): 搜索引擎显示的标题（通常包含长尾词）。
*   `seo_keywords` (TEXT): 页面关键词。
*   `seo_description` (TEXT): 页面描述（用于搜索结果摘要）。
*   `structured_data` (TEXT): JSON-LD 结构化数据（用于 Google 富媒体搜索结果）。

### 2.2 核心表结构优化

#### A. 需求市场表 (`requirements`) - *增强运营属性*
```sql
ALTER TABLE requirements ADD COLUMN is_featured INTEGER DEFAULT 0; -- 是否推荐/精选
ALTER TABLE requirements ADD COLUMN is_urgent INTEGER DEFAULT 0;   -- 是否加急
ALTER TABLE requirements ADD COLUMN admin_notes TEXT;              -- 管理员内部备注（记录撮合进度）
ALTER TABLE requirements ADD COLUMN tags TEXT;                     -- 标签（用于匹配供应商）
```

#### B. 产品表 (`products`) - *独立且完善*
从供应商附庸转变为**核心资产**。
```sql
CREATE TABLE IF NOT EXISTS products (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  product_id TEXT UNIQUE,
  supplier_id TEXT,          -- 关联供应商
  name TEXT,                 -- 产品名称
  slug TEXT UNIQUE,          -- SEO URL
  model TEXT,                -- 型号
  series TEXT,               -- 系列
  primary_category TEXT,
  secondary_category TEXT,
  summary TEXT,              -- 短摘要
  description TEXT,          -- 详细介绍 (HTML/Markdown)
  parameters_json TEXT,      -- 技术参数
  cover_image TEXT,          -- 封面图
  gallery_json TEXT,         -- 图集
  documents_json TEXT,       -- 关联文档 (PDF手册等)
  seo_title TEXT,
  seo_keywords TEXT,
  seo_description TEXT,
  status TEXT,               -- active, offline
  is_featured INTEGER,       -- 首页推荐
  created_at TEXT,
  updated_at TEXT
);
CREATE INDEX idx_products_slug ON products(slug);
```

#### C. 资源文件表 (`assets`) - *新增*
统一管理所有上传的文件，实现“一次上传，多处复用”。
```sql
CREATE TABLE IF NOT EXISTS assets (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  asset_id TEXT UNIQUE,
  filename TEXT,             -- 原文件名
  r2_key TEXT,               -- R2 存储路径 (e.g., 2025/01/abc.jpg)
  public_url TEXT,           -- CDN 访问地址
  file_type TEXT,            -- image, pdf, video
  file_size INTEGER,
  alt_text TEXT,             -- 图片 ALT 属性 (SEO)
  uploaded_by TEXT,
  created_at TEXT
);
```

## 3. API 接口设计 (Cloudflare Workers)

### 3.1 资源管理接口 (Resource API)
*   `POST /api/admin/assets/upload`: 上传文件到 R2，并在 D1 `assets` 表记录。
    *   *特性*：支持自动重命名、图片压缩（可选）、生成 WebP。
*   `GET /api/admin/assets`: 浏览资源库（支持按类型、日期筛选）。
*   `DELETE /api/admin/assets/:id`: 删除文件。

### 3.2 关联增强接口
*   `GET /api/admin/products/search`: 供“案例编辑”时搜索关联产品。
*   `GET /api/admin/suppliers/search`: 供“产品编辑”时搜索归属供应商。

## 4. 后台管理界面实施 (`management.html`)

### 4.1 界面布局重构
侧边栏按照**业务逻辑**重新分组：

*   **运营中心**
    *   📊 仪表盘 (Dashboard)
    *   📢 需求市场 (Requirements) - *含撮合管理*
    *   💬 报价管理 (Quotes)
*   **内容中心 (SEO重点)**
    *   📦 产品库 (Products) - *核心模块*
    *   📰 新闻资讯 (News)
    *   📘 应用案例 (Cases)
    *   🎪 展会活动 (Exhibitions)
*   **资源中心**
    *   🖼️ 媒体库 (Media Library) - *图片/文档统一管理*
*   **系统设置**
    *   🏢 供应商管理 (Suppliers)
    *   👥 发布方管理 (Demanders)
    *   ⚙️ 账号与权限

### 4.2 关键模块功能细化

#### A. 需求市场 (运营视角)
*   **列表页**：增加“状态标签”（待审核、已公开、重点跟进）。
*   **操作栏**：增加“置顶”、“加急”开关。
*   **详情页**：
    *   显示“匹配供应商推荐”：根据需求分类/标签，列出库中相关的供应商。
    *   显示“内部备注”：记录管理员联系发布方的进度。

#### B. 产品发布 (SEO 视角)
*   **编辑页布局**：
    *   **左侧（基础信息）**：名称、型号、供应商、分类、参数。
    *   **中间（内容详情）**：富文本/Markdown编辑器，支持从“媒体库”直接插入图片/PDF卡片。
    *   **右侧（SEO 设置）**：
        *   **Slug**: 自动根据名称生成拼音/英文，支持手动修改。
        *   **Meta Title**: 实时预览搜索结果样式。
        *   **Keywords**: 标签式输入。
    *   **底部（关联）**：选择“相关案例”、“相关文档”。

#### C. 媒体库 (Media Library)
*   **弹窗/独立页**：所有上传控件点击后均弹出媒体库。
*   **功能**：
    *   拖拽上传。
    *   图片预览、复制 URL、复制 Markdown 格式。
    *   文件复用：即之前传过的图，可以直接选，不用重复传。

## 5. 前端融合与 SEO 策略

### 5.1 URL 结构标准化
利用 Hugo 的路由能力，结合 D1 数据：
*   产品页：`/products/{category}/{slug}/` (而非 ID)
*   案例页：`/cases/{slug}/`
*   资讯页：`/news/{category}/{slug}/`

### 5.2 静态生成 + 动态回落 (Hybrid Rendering)
*   **核心页面（首页、产品列表、核心产品页）**：
    *   建议利用 Hugo 构建时通过 `getJSON` 获取部分 D1 数据生成静态 HTML，确保 100% SEO 友好。
    *   或者使用 Cloudflare Workers 的 **HTMLRewriter** 技术，在边缘端动态注入 Meta 标签和核心内容（这对爬虫非常友好）。
*   **长尾页面/实时性强的页面（需求详情）**：
    *   保持 CSR (客户端渲染)，但通过 Workers 动态注入 `Open Graph` 和 `Title/Description` 标签，确保分享在微信/LinkedIn 时显示正常。

### 5.3 统一内容关联
*   **产品页**自动展示：关联的“应用案例”、关联的“下载资料（PDF）”。
*   **案例页**自动展示：文中用到的“相关产品卡片”。

## 6. 执行步骤与时间表 (优化版)

### 第一阶段：基础设施与资源库（预计 2 天）
1.  **数据库升级**：执行新的 Schema，创建 `products`, `news`, `cases`, `assets` 表及 SEO 字段。
2.  **R2 集成**：配置 Cloudflare R2，开发 `upload` API。
3.  **媒体库开发**：在后台实现基础的图片上传与列表选择功能。

### 第二阶段：核心内容模块（预计 3 天）
1.  **产品管理开发**：实现带 SEO 设置、参数编辑、关联供应商的完整编辑器。
2.  **案例/新闻开发**：复用产品编辑器的逻辑，实现内容发布。
3.  **数据迁移**：编写脚本，将现有 Markdown 文件中的产品/新闻导入 D1 数据库。

### 第三阶段：需求市场运营升级（预计 1 天）
1.  **字段扩展**：增加置顶、备注等字段。
2.  **后台优化**：更新需求列表 UI，支持运营操作。

### 第四阶段：前端重构与 SEO 对接（预计 3-4 天）
1.  **路由改造**：前端页面支持基于 Slug 的路由解析。
2.  **模板更新**：修改 Hugo 模板或 JS 逻辑，展示关联内容（产品关联案例等）。
3.  **SEO 验证**：检查动态加载内容的收录情况，必要时配置 HTMLRewriter。

## 7. 总结
此方案将系统从一个简单的“数据录入后台”升级为**“企业级内容运营系统”**。
*   **对运营人员**：提供了强大的 SEO 工具、统一的素材库和灵活的需求撮合能力。
*   **对供应商**：被纳入统一管理体系，其产品由平台专业发布，质量更高。
*   **对 SEO**：通过 Slug、结构化数据和内链闭环，最大化搜索引擎友好度。
