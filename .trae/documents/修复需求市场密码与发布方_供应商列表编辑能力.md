## 问题定位
- 需求详情解锁联系方式支持两种密码：查看密码与供应商通行密码。列表页已支持两者（layouts/requirements/list.html:691–744），详情页模板仅试查看密码（layouts/requirements/single.html:33–53），导致“应输入供应商密码”的诉求未实现。
- 发布后未进入“发布方列表”：发布方聚合目前依赖手动/运维入口（POST /api/admin/import-demanders，cloudflare/src/index.js:936–980），创建需求时未自动 upsert 到 demanders。
- 列表显示与可编辑：供应商列表已返回平明密码并支持 PATCH（cloudflare/src/index.js:480–547），发布方列表无“密码”字段；现有 Demanders 仅 metadata_json，不能显示/编辑专用密码。
- 发布方入口页面（static/entry-demand.html）仅支持“查看密码”工作流（/api/requirements/by-password 与 /api/quotes?view_password），没有“发布方专用密码会话”。

## 目标
- 详情页解锁优先使用供应商密码，兼容查看密码，文案明确。
- 需求创建后自动写入/更新发布方（demanders），确保管理页能看到。
- 管理后台：发布方与供应商列表均显示企业信息与各自密码，并支持字段编辑。
- 发布方入口：支持“发布方专用密码”登录，或继续兼容查看密码。

## 具体改动
1) 前端：需求详情页密码检验
- 更新 layouts/requirements/single.html：校验顺序改为先 supplier_access_password，再回退 view_password；失败提示统一。
- 文案改为“供应商授权密码或查看密码”。

2) 后端：创建需求自动聚合发布方
- 在 POST /api/requirements（cloudflare/src/index.js:193–225）成功写入后，立即以 contact_company 作为键 upsert 一条 demanders 记录（name/phone/email/department 与 metadata_json.contact_public、allow_open_quotes），并将默认的 publisher_password_plain 设为同一批需求的 view_password_plain（或单独生成）。

3) 后端：发布方专用密码与会话
- 在 demanders 表新增列 publisher_password_plain（或在 metadata_json 中增加 password_plain），并提供：
  - POST /api/demanders/session：按 publisher_password_plain 验证并返回发布方基本信息；
  - GET /api/demanders/requirements?company=...：列出该公司发布的需求（可分页）。
- 管理端 API 增强：
  - GET /api/admin/demanders 返回 password_plain 字段；
  - PATCH /api/admin/demanders/:id 支持更新包括 password_plain 在内的各字段；
  - GET /api/admin/demanders/export CSV 增加“需密码/公开”与 password_plain 导出。

4) 前端：管理页面增强（static/management.html）
- “需求方”板块：表格新增“密码”列；编辑弹窗支持公司、联系人、电话、邮箱、部门、公开开关、是否需密码、专用密码；保存走 PATCH。
- “重新统计并加载”按钮调用 POST /api/admin/import-demanders，然后再 GET 列表与 GET stats。
- “供应商”板块：保留 access_password_plain 显示与编辑。

5) 前端：发布方入口（static/entry-demand.html）
- 表单输入支持两种模式：
  - 发布方密码模式：调用 POST /api/demanders/session 成功后按公司加载其全部需求与报价；
  - 查看密码模式：保持现有 /api/requirements/by-password 工作流。
- UI 提示与失败路径清晰，导出 CSV 维持现有逻辑。

## 风险与取舍
- 新增列与会话接口需对 D1 进行轻量迁移；按现有 ensureSchema 方式追加列并保持兼容。
- 明文密码是过渡方案；后续计划迁移到哈希存储与短期令牌。
