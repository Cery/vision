# 二、设计原则与阶段划分

**初级阶段（快上线、低成本）**

- 使用 Netlify Forms 接收表单；表单数据进入 Netlify 控制台并触发邮件通知给平台人员；
- 人工审核后由平台工作人员用手机号/邮件手动发送“查看密码 + 查看链接”给发布者（或直接电话通知）；
- 供应商在需求市场页面无需先登录查看公开信息；若要查看完整信息或在线报价，供应商在详情页输入“查看密码”；
- 密码验证采用 Netlify Function + Airtable（或 Google Sheet）做后端验证（轻量、安全性高于纯前端）。

**中级阶段（自动化）**

- 使用 Netlify Function 自动发送短信（Twilio/国内短信通道），并把需求写入 Airtable；
- 供应商购买 access 或平台发放供应商长期“查看令牌”时可使用过期机制。

**高级阶段（自研后台）**

- 独立后端（Node/Go/Python）与数据库（Postgres/Mongo），可实现权限、企业供需对接、会员制、付费查看等。

# 五、Netlify Functions（示例）

> 注意：Netlify Functions 需要放在仓库 `netlify/functions/`（或 `functions/`）目录并在 `netlify.toml` 注册。下面示例以 Node.js 为例。

## 1) `verifyPassword.js` （验证密码，建议用 Airtable 存储哈希）

功能：接收 `requirementID` 与 `password`，查询 Airtable 中该需求记录的 `ViewPasswordHash`，比较（使用 bcrypt 或 sha256 比对），返回是否有效与完整信息（当密码正确时返回公司/联系人等私密字段）。

示例（简化，用 SHA256；生产建议用 bcrypt）：

```
// netlify/functions/verifyPassword.js
const fetch = require('node-fetch');
const crypto = require('crypto');

exports.handler = async function(event) {
  if (event.httpMethod !== 'POST') return { statusCode: 405, body: 'Method Not Allowed' };
  const body = JSON.parse(event.body);
  const { requirementID, password } = body;

  // Airtable 配置（替换成你的）
  const AIRTABLE_BASE = process.env.AIRTABLE_BASE;
  const AIRTABLE_KEY = process.env.AIRTABLE_KEY;
  const table = 'Requirements';

  try {
    // 查询 Airtable（过滤 RequirementID）
    const url = `https://api.airtable.com/v0/${AIRTABLE_BASE}/${table}?filterByFormula={RequirementID}='${requirementID}'`;
    const res = await fetch(url, {
      headers: { Authorization: `Bearer ${AIRTABLE_KEY}` }
    });
    const data = await res.json();
    if (!data.records || data.records.length === 0) {
      return { statusCode: 200, body: JSON.stringify({ valid:false }) };
    }
    const record = data.records[0].fields;
    const storedHash = record.ViewPasswordHash || '';

    // 简单 sha256 比对（生产请使用更安全的 hash+salt）
    const hash = crypto.createHash('sha256').update(password).digest('hex');
    if (hash === storedHash) {
      // 返回私密信息
      return {
        statusCode: 200,
        body: JSON.stringify({
          valid: true,
          data: {
            company: record.ContactCompany,
            contact: record.ContactName,
            phone: record.ContactPhone
          }
        })
      };
    } else {
      return { statusCode: 200, body: JSON.stringify({ valid:false }) };
    }
  } catch (err) {
    console.error(err);
    return { statusCode: 500, body: 'Internal Error' };
  }
};
```

**环境变量**（在 Netlify 网站设置环境变量）：

- `AIRTABLE_BASE`、`AIRTABLE_KEY`

**说明**：

- 在初级阶段，你可以把 `ViewPasswordHash` 预先手动写入 Airtable（由平台人员在人工发送密码时同时写入哈希）；
- 更安全的流程：在 Netlify Function 内接收表单后把明文密码转换为哈希并写入 Airtable，再删除 Netlify 表单里的明文（需要实现函数触发链）。

## 2) `sendSMS.js`（可选，自动发送短信，使用 Twilio 示例）

> 仅示例。国内短信需要用国内服务商（腾讯云、阿里云），接口不同。

```
// netlify/functions/sendSMS.js
const Twilio = require('twilio');

exports.handler = async function(event) {
  if (event.httpMethod !== 'POST') return { statusCode: 405 };
  const body = JSON.parse(event.body);
  const { phone, message } = body;

  const accountSid = process.env.TWILIO_SID;
  const authToken = process.env.TWILIO_TOKEN;
  const fromNumber = process.env.TWILIO_FROM;

  const client = Twilio(accountSid, authToken);
  try {
    const msg = await client.messages.create({
      body: message,
      from: fromNumber,
      to: phone
    });
    return { statusCode: 200, body: JSON.stringify({ sid: msg.sid }) };
  } catch (err) {
    console.error(err);
    return { statusCode: 500, body: 'SMS send failed' };
  }
};
```

**运行说明**：在自动化阶段，发布表单后由 Netlify Function 调用该接口发送短信（需留意 Twilio 在国内的可达性及费用）。

# 六、前端密码/报价交互细节（工作流）

## 1) 发布方工作流（初级）

1. 发布方填写表单并提交（前端生成 `RequirementID` 和 `ViewPassword`，同时在 Netlify 表单中保存明文）；
2. 系统（或平台人员）在 Netlify 后台收到通知；平台人员登录 Airtable：
   - 将该条需求的 `ViewPassword` 转为哈希写入 `ViewPasswordHash` 字段；
   - 若公开则把 `Status` 改为 `公开`；
3. 平台人工用短信/电话/邮件把查看链接 `https://visndt.com/requirements/<id>?` 与查看密码发送给发布方；
4. 发布方使用该密码查看报价或管理报价权限。

## 2) 供应商工作流

1. 浏览需求市场（所有 `Status=公开` 的需求）；
2. 点击某条需求详情页：
   - 如果请求完整信息或报价，则弹出密码输入框；
   - 供应商输入密码后，前端调用 `verifyPassword` Netlify Function 校验；
   - 校验通过后显示完整信息并展示报价表单（通过 Netlify Forms 提交报价）；
3. 报价进入 `Quotes` 表（Airtable），并可在后台通知发布方（人工 / 后期自动）。

# 七、权限与安全建议（必须重视）

- **绝不要在前端以明文形式暴露公司联系方式**。初级阶段不能直接在静态 HTML 中硬编码私密信息；
- **密码不要以明文长时间存放**。建议：
  - Netlify 表单保存明文仅用于人工处理后立即删除；
  - 自动化后端将明文替换为哈希（bcrypt 优先）并保存哈希；
- **密码验证应在后端完成**，不要在前端直接比对（否则容易被抓取）；
- **API 密钥存放在 Netlify 环境变量**，不要提交到 Git 仓库；
- **日志和监控**：Netlify 控制台 + Airtable / Google Sheets 记录所有操作以便审计。

# 八、运维、成本与第三方服务选择建议

## 短信服务（对比建议）

- 国内：腾讯云短信、阿里云短信（需要企业认证、模板审核、费用按条计费）；
- 国外：Twilio（国际覆盖）、Nexmo（Vonage）等（易用但成本/可达性差异）；
- 初级建议：人工短信/电话/邮件代替自动短信，节省成本并可以人工审核质量。

## Airtable vs Google Sheets

- Airtable：API 更方便、字段类型丰富、适合做中台（推荐）；
- Google Sheets：免费、熟悉但接口略繁琐（也可用，但并发/稳定性需注意）。

## Netlify 费用

- Netlify 免费层支持基本静态站 + Functions（有调用限制）；若访问量或函数调用多，需升级付费计划。
