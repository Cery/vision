# 需求市场：免费实现方案与迁移指南

本文档给出三种零成本/低成本的实现路径，并提供配置步骤与优缺点分析。目标是在不使用 Airtable 的情况下保持功能完整且易维护。

## 推荐方案 A：GitHub JSON 持久化（已在项目中接入）

思路：将需求数据以数组形式保存在仓库中的 `data/requirements.json`，发布接口通过 GitHub Contents API 进行追加提交；列表接口可从 GitHub Raw 读取或使用静态文件（发布后触发站点重建）。

已做改造：
- 发布接口：`netlify/functions/createRequirement.js` 新增 GitHub 持久化分支（优先），失败时回落到 Airtable 或本地 JSON。
- 列表接口：`netlify/functions/listRequirements.js` 新增 GitHub Raw 回退，能直接读取仓库最新的 JSON 内容。

环境变量（Netlify 上配置 Build & Functions 环境变量）：
- `GITHUB_TOKEN` 或 `GH_TOKEN`：建议使用 Fine-grained PAT，仅对目标仓库授予 contents: read/write 权限。
- `GITHUB_OWNER` 或 `GH_OWNER`：仓库所有者，例如 `your-org` 或 `your-username`。
- `GITHUB_REPO` 或 `GH_REPO`：仓库名，例如 `vision`。
- `GITHUB_BRANCH`：分支名，默认 `main`。
- `GITHUB_REQUIREMENTS_PATH`：JSON 路径，默认 `data/requirements.json`。

工作流程：
1. 用户提交表单，函数将记录（包含 `RequirementID`、联系方式、参数等）追加到 `requirements.json` 并提交到 GitHub。
2. Netlify 如绑定同一仓库，会在提交后自动触发一次构建部署，静态站点中的 `data/requirements.json` 随之更新。
3. 列表展示可以：
   - 使用函数的 GitHub Raw 回退，直接读取最新 JSON（无需等待重建）；
   - 或直接读取静态文件（重建后一致）。

优点：
- 完全免费（GitHub + Netlify 免费层）；无需独立数据库。
- 数据版本化、安全，可审计；支持回滚。
- 与 Hugo/静态数据天然契合。

注意事项：
- 若仓库为私有，Raw 读取需要 token 或通过函数代理；公开仓库无需 token 即可读。
- 写入走 PAT，有速率限制与构建分钟数占用（Netlify 免费层通常足够）。

## 方案 B：Cloudflare D1（SQLite）+ Workers

思路：使用 Cloudflare 免费层，D1 提供 SQL 存储，Workers 暴露 API。发布与列表都走 Workers，无需重建站点。

步骤要点：
- 创建 D1 数据库与表（`requirements`）。
- 编写 Worker 路由：`POST /requirements` 保存、`GET /requirements` 列举。
- 在前端将原 `/.netlify/functions/...` 改为指向 Workers 路径。

优点：
- 即时读写，无需重建；查询灵活。

注意：
- 需要 Cloudflare 账号与基础配置；比 GitHub JSON 略复杂。

## 方案 C：Google Sheets + Apps Script Web App（极简）

思路：表单数据直接写入 Google 表格；通过 Apps Script 发布 Web App，提供 `doPost`/`doGet` 接口。前端读写该 Web App。

优点：
- 快速上手、零服务器成本；适合早期原型。

缺点：
- 权限与限额受 Google 约束；结构化与查询能力有限。

## 迁移建议（从 Airtable → 推荐方案 A）

1. 在 GitHub 生成 Fine-grained PAT，授权目标仓库 contents: read/write。
2. 在 Netlify 项目设置中添加上述环境变量。
3. 保持仓库中存在 `data/requirements.json`（若不存在，首次提交会自动创建）。
4. 列表页优先使用函数接口（已带 GitHub Raw 回退），可即时看到最新数据。
5. 待运行一段时间稳定后，移除 Airtable 相关变量与函数逻辑（非必须）。

## 安全与合规

- 不在客户端暴露 PAT；所有写入通过服务端函数执行。
- 敏感字段（如电话号码）如需脱敏，可在列表接口中进行裁剪或仅展示 `PublicPreview`。
- 查看密码（如启用）仅保存在 GitHub JSON 中，不在前端日志输出。
