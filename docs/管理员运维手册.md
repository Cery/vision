## 一、系统概述

### 1.1 系统架构

Vision NDT平台采用混合架构：
- **前端**: Hugo静态站点（Netlify托管）
- **后端**: Cloudflare Workers + D1数据库
- **存储**: Cloudflare R2（图片和文件）
- **管理后台**: 统一管理入口 `/admin/dashboard.html`

### 1.2 核心功能模块

- **需求市场**: 需求发布、报价管理、供应商撮合
- **内容管理**: 产品、新闻、案例管理
- **供应商管理**: 供应商信息、标签管理
- **数据管理**: 备份、恢复、导入导出
- **运营工具**: 数据报表、操作日志、通知管理

### 1.3 访问地址

- **管理后台**: `https://www.visndt.com/admin/dashboard.html`
- **API地址**: `https://api.visndt.com`
- **内容管理器**: `https://www.visndt.com/admin/tools/content-manager.html`
- **需求管理**: `https://www.visndt.com/admin/tools/requirements-admin.html`

## 二、快速开始

### 2.1 首次登录

1. 访问管理后台：`https://www.visndt.com/admin/dashboard.html`
2. 输入管理员账号和密码
3. 登录成功后自动跳转到仪表板

### 2.2 管理员账号

**方式一：数据库用户（推荐）**
- 账号存储在`admin_users`表
- 支持JWT token认证
- 密码建议使用环境变量配置

**方式二：环境变量（向后兼容）**
- 使用`ADMIN_USER`和`ADMIN_PASSWORD`环境变量
- 支持传统的`X-Admin-Key`认证方式

### 2.3 环境配置

在Cloudflare Workers环境变量中配置：
```
ADMIN_USER=your_username
ADMIN_PASSWORD=your_secure_password
JWT_SECRET=your_jwt_secret_key
ADMIN_KEY=your_admin_key (向后兼容)
```

## 三、登录与认证

### 3.1 登录方式

#### 方式一：Web界面登录
1. 访问 `/admin/dashboard.html`
2. 输入用户名和密码
3. 系统返回JWT token并存储在localStorage

#### 方式二：API登录
```bash
curl -X POST https://api.visndt.com/api/admin/login \
  -H "Content-Type: application/json" \
  -d '{
    "username": "your_username",
    "password": "your_password"
  }'
```

**响应示例**:
```json
{
  "ok": true,
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user": {
    "userId": "admin-001",
    "username": "admin",
    "role": "admin"
  }
}
```

### 3.2 Token使用

**在API请求中使用Token**:
```bash
# 方式一：Bearer Token（推荐）
curl -X GET https://api.visndt.com/api/admin/stats \
  -H "Authorization: Bearer YOUR_JWT_TOKEN"

# 方式二：X-Admin-Key（向后兼容）
curl -X GET https://api.visndt.com/api/admin/stats \
  -H "X-Admin-Key: YOUR_ADMIN_KEY"
```

### 3.3 Token过期

- Token有效期为24小时
- 过期后需要重新登录
- 建议在Token过期前刷新

## 五、功能模块详解

### 5.1 需求市场管理

#### 5.1.1 需求列表管理

**访问路径**: `/admin/tools/requirements-admin.html`

**功能**:
- 查看所有需求列表
- 筛选需求（状态、进度、是否公开联系方式）
- 编辑需求信息
- 删除需求
- 查看报价列表

**操作步骤**:
1. 登录管理后台
2. 点击侧边栏"需求市场"
3. 在需求列表中点击"详情"查看或编辑
4. 在需求详情中可以：
   - 修改状态（公开/隐私/关闭）
   - 修改进度（发布中/接洽中/已完成）
   - 设置查看密码
   - 设置报价密码
   - 添加管理员备注

#### 5.1.2 需求撮合

**功能**: 自动匹配适合的供应商

**使用方式**:
```bash
POST /api/admin/match-suppliers
{
  "requirement_id": "REQ-20250120-001"
}
```

**返回结果**:
- 按匹配度排序的供应商列表（Top 20）
- 每个供应商显示匹配分数和匹配关键词

**操作建议**:
1. 在需求详情页使用撮合功能
2. 查看匹配结果，联系高分供应商
3. 可以手动推送需求给匹配供应商

#### 5.1.3 报价管理

**功能**:
- 查看需求的所有报价
- 更新报价状态（已提交/审核中/已通过/已拒绝/中标）
- 导出报价数据

**操作步骤**:
1. 在需求详情中点击"报价"按钮
2. 查看报价列表
3. 选择报价，更新状态
4. 可以导出为CSV格式

### 5.2 内容管理

#### 5.2.1 产品管理

**访问路径**: `/admin/tools/content-manager.html`

**功能**:
- 产品列表查看
- 产品创建和编辑
- 产品分类管理
- SEO设置
- 图片和文档管理

**操作步骤**:
1. 进入内容管理器
2. 选择"产品管理"
3. 点击"新建"创建产品
4. 填写产品信息：
   - 基本信息（名称、型号、系列）
   - 分类信息（主分类、次分类）
   - 详细描述
   - SEO信息（标题、关键词、描述）
   - 图片和文档

#### 5.2.2 新闻管理

**功能**:
- 新闻列表管理
- 新闻创建和编辑
- 新闻分类（技术文章、行业资讯、展会信息）
- 新闻发布状态管理

**操作步骤**:
1. 进入内容管理器
2. 选择"新闻管理"
3. 创建或编辑新闻
4. 设置分类、标签、SEO信息
5. 设置发布状态

#### 5.2.3 案例管理

**功能**:
- 应用案例列表
- 案例创建和编辑
- 行业分类
- 关联产品

**操作步骤**:
1. 进入内容管理器
2. 选择"案例管理"
3. 创建或编辑案例
4. 选择行业分类
5. 关联相关产品

### 5.3 供应商管理

#### 5.3.1 供应商列表

**功能**:
- 查看所有供应商
- 搜索供应商
- 编辑供应商信息
- 管理供应商状态（待审核/启用/停用/禁用）

**操作步骤**:
1. 进入内容管理器
2. 选择"供应商管理"
3. 查看供应商列表
4. 点击"编辑"修改供应商信息

#### 5.3.2 供应商标签管理

**功能**: 为供应商添加标签，用于需求撮合匹配

**操作方式**:
- 通过API添加标签：`POST /api/admin/suppliers/:id/tags`
- 或直接在供应商编辑界面添加

**标签建议**:
- 产品类别：如"内窥镜"、"检测相机"
- 应用领域：如"航空航天"、"汽车制造"
- 技术特点：如"高清"、"便携"

### 5.4 数据备份

#### 5.4.1 创建备份

**操作步骤**:
1. 登录管理后台
2. 点击侧边栏"数据备份"
3. 点击"创建备份"按钮
4. 选择备份类型（全量/增量）
5. 选择要备份的表（默认全选）
6. 确认创建

**备份内容**:
- 备份文件存储在R2（如果配置）或返回JSON
- 备份元数据记录在`backup_history`表

#### 5.4.2 查看备份历史

**功能**:
- 查看所有备份记录
- 查看备份详情（类型、大小、表列表、创建时间）
- 下载备份文件（如果存储在R2）

**操作步骤**:
1. 进入"数据备份"页面
2. 查看备份列表
3. 点击备份记录查看详情

#### 5.4.3 备份建议

- **频率**: 建议每日备份一次
- **保留**: 建议保留最近30天的备份
- **验证**: 定期验证备份文件完整性

### 5.5 数据报表

#### 5.5.1 报表类型

**概览报表** (`type=overview`):
- 需求统计（按状态、进度）
- 报价统计（按状态）
- 供应商活跃度

**需求报表** (`type=requirements`):
- 需求状态分布
- 需求进度分布
- 需求时间趋势

**报价报表** (`type=quotes`):
- 报价状态分布
- 报价金额统计
- 报价时间趋势

**供应商报表** (`type=suppliers`):
- 供应商活跃度排名
- 报价数量统计
- 供应商地区分布

#### 5.5.2 使用方式

**Web界面**:
1. 登录管理后台
2. 点击"数据报表"
3. 选择报表类型
4. 设置时间范围（可选）
5. 查看报表数据

**API调用**:
```bash
GET /api/admin/reports?type=overview&start_date=2025-01-01&end_date=2025-01-31
```

### 5.6 操作日志

#### 5.6.1 日志查询

**功能**:
- 查看所有管理员操作记录
- 按模块、操作类型、用户筛选
- 分页浏览

**操作步骤**:
1. 登录管理后台
2. 点击"操作日志"
3. 使用筛选条件查询
4. 查看日志详情

#### 5.6.2 日志字段说明

- **用户**: 执行操作的管理员
- **操作**: 操作类型（login, create, update, delete等）
- **模块**: 功能模块（auth, requirements, products等）
- **资源**: 操作的资源类型和ID
- **时间**: 操作时间
- **IP地址**: 操作来源IP
- **详情**: 操作详细信息（JSON格式）

### 5.7 通知管理

#### 5.7.1 创建通知

**功能**: 创建通知记录（待管理员手动发送）

**操作步骤**:
1. 登录管理后台
2. 点击"通知管理"
3. 点击"创建通知"
4. 填写通知信息：
   - 通知类型（email/sms）
   - 收件人邮箱/电话
   - 通知标题
   - 通知内容
5. 创建后状态为"pending"

#### 5.7.2 通知发送流程

**当前流程**（人工发送）:
1. 创建通知记录
2. 管理员查看通知列表
3. 通过电话/短信/邮件手动发送
4. 更新通知状态为"已发送"

**未来流程**（自动发送）:
- 接入邮件服务（SMTP/第三方API）
- 接入短信服务（Twilio/腾讯云/阿里云）
- 自动发送并更新状态

#### 5.7.3 通知模板

**功能**: 创建通知模板，便于重复使用

**模板字段**:
- 模板名称
- 通知类型
- 标题模板（支持变量）
- 内容模板（支持变量）
- 变量列表

**使用方式**:
1. 创建模板
2. 创建通知时选择模板
3. 填写变量值
4. 系统自动替换变量生成最终内容

## 七、数据管理

### 7.1 数据同步

#### 从静态站点同步数据

**功能**: 将Hugo生成的静态索引同步到数据库

**操作步骤**:
1. 确保静态站点已生成`/data/index.json`
2. 调用同步API：
   ```bash
   POST /api/admin/import-news?base=https://www.visndt.com/data
   POST /api/admin/import-cases?base=https://www.visndt.com/data
   POST /api/admin/import-products?base=https://www.visndt.com/data
   ```

**同步策略**:
- 使用upsert机制，避免重复数据
- 支持ID和slug双标识
- 同步完成后更新`sync_meta`

### 7.2 数据导出

#### CSV导出

**使用场景**:
- 导出需求列表用于分析
- 导出供应商信息用于联系
- 导出报价数据用于统计

**操作方式**:
1. 通过API导出：`GET /api/admin/export?table=requirements&format=csv`
2. 浏览器会自动下载CSV文件
3. 用Excel或其他工具打开

#### JSON导出

**使用场景**:
- 数据备份
- 数据迁移
- 数据分析

**操作方式**:
```bash
GET /api/admin/export?table=requirements&format=json
```

### 7.3 数据备份与恢复

#### 备份策略

**建议备份频率**:
- 每日自动备份（通过定时任务）
- 重要操作前手动备份
- 重大更新前完整备份

**备份内容**:
- 核心业务表（requirements, suppliers, quotes）
- 内容表（products, news, cases）
- 系统表（admin_users, admin_logs）

#### 恢复流程

**注意**: 数据恢复功能待实现，当前仅支持备份

**计划恢复流程**:
1. 选择备份文件
2. 选择要恢复的表
3. 确认恢复操作
4. 验证恢复结果

## 八、常见问题

### 8.1 登录问题

**Q: 忘记密码怎么办？**
A: 联系系统管理员重置密码，或通过环境变量`ADMIN_PASSWORD`设置新密码。

**Q: Token过期怎么办？**
A: 重新登录获取新Token。Token有效期为24小时。

**Q: 登录后提示"Unauthorized"？**
A: 检查：
1. Token是否正确
2. Token是否过期
3. 用户状态是否为"active"

### 8.2 功能使用问题

**Q: 如何批量更新需求状态？**
A: 使用批量更新API：
```bash
POST /api/admin/markets
{
  "applyToAll": true,
  "status": "公开"
}
```

**Q: 需求撮合没有结果？**
A: 检查：
1. 供应商是否添加了标签
2. 需求的关键词是否明确
3. 供应商产品分类是否匹配

**Q: 备份文件在哪里？**
A: 
- 如果配置了R2，文件存储在R2的`backups/`目录
- 如果未配置R2，备份数据在API响应中返回

### 8.3 数据问题

**Q: 数据同步失败？**
A: 检查：
1. 静态站点索引文件是否存在
2. 索引文件格式是否正确
3. API地址是否正确

**Q: 导出数据为空？**
A: 检查：
1. 表名是否正确
2. 表中是否有数据
3. 是否有权限访问

## 九、故障排查

### 9.1 API错误

#### 401 Unauthorized
**原因**: 认证失败
**解决**:
1. 检查Token是否正确
2. 检查Token是否过期
3. 重新登录获取新Token

#### 404 Not Found
**原因**: API端点不存在或路径错误
**解决**:
1. 检查API路径是否正确
2. 检查请求方法（GET/POST）是否正确

#### 500 Internal Server Error
**原因**: 服务器内部错误
**解决**:
1. 查看Cloudflare Workers日志
2. 检查数据库连接
3. 检查环境变量配置

### 9.2 数据库问题

#### 表不存在
**原因**: Schema未初始化
**解决**:
1. 确保`ensureSchema()`函数已执行
2. 手动创建缺失的表

#### 数据不一致
**原因**: 静态站点与数据库不同步
**解决**:
1. 重新同步数据
2. 检查同步日志
3. 手动修复不一致数据

### 9.3 性能问题

#### API响应慢
**原因**: 数据量大或查询未优化
**解决**:
1. 使用分页查询
2. 添加索引
3. 优化查询语句

#### 备份超时
**原因**: 数据量过大
**解决**:
1. 分批备份
2. 只备份必要表
3. 使用异步备份（待实现）
