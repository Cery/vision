# 运维手册（Vision NDT）

## 目标与范围
- **全自动化执行**：系统支持自动化运维流程，减少人工干预。
- **统一管理后台**：保留单一 `/admin` 主内容管理后台，清理无效后台页面。
- **角色入口分离**：发布方管理入口、供应商管理入口独立运行。
- **工具页面独立**：保留单独的 `/tool` 工具页面用于辅助功能。
- 统一后台 API 行为与路由匹配，消除"0 数据"与保存异常。
- 支持以 `ID` 或 `slug` 双标识进行 CRUD，便于与静态站点内容同步。
- 引入原子化 upsert，避免重复 `slug` 导致的保存失败。
- 可视化同步元数据，后台仪表板可见导入统计与时间。
- 统一需求列表前后端显示逻辑，修复审批与公开状态不一致。
- 完成供应商注册、会话登录与后台管理整合。
- 增强资产（R2）管理与后台批量操作能力。

## 环境与配置

### 管理员认证信息
- **主内容管理后台**：`/admin/index.html` 或 `/admin/dashboard.html`
- **登录用户名**：本地默认见 `cloudflare/.dev.vars`（通常为 `visndt`）
- **登录密码**：本地默认见 `cloudflare/.dev.vars`（通常为 `admin123456`）
- **管理员密钥（Admin-Key）**：本地默认见 `cloudflare/.dev.vars`（通常为 `@Aa123456`）；生产环境请通过 Worker Secret 管理（不要写入仓库）
- **管理员密钥头**：`X-Admin-Key` 或 `x-admin-key`（大小写均可）

### 重要环境变量
- `SYNC_BASE_URL`：内容索引源（如 `https://www.visndt.com/data`）。
- `ADMIN_PASSWORD`（可选）：管理员口令（用于 `/api/admin/verify` POST）。
- `ADMIN_KEY`：管理员密钥（建议仅以 Secret 形式配置）。
- `ADMIN_USER`：管理员用户名。
- `DEFAULT_SUPPLIER_PASSWORD`（可选）：定时任务为所有供应商设置默认通行密码。
- `DEFAULT_REQUIREMENT_PASSWORD`（可选）：为需求设置默认查看密码（仅空值时生效）。
- 系统配置表：`system_config` 存储同步元数据（key=`sync_meta`）。

## 本地开发环境启动（推荐流程）

说明：仓库根目录的 `package.json` 中存在对 `server.js`、`content-server.js`、`product-server.js`、`start-optimized.js` 的脚本引用，但这些文件在当前仓库中并不存在，`npm start` / `npm run dev` 可能无法直接使用。建议以“**Hugo + Cloudflare Worker（wrangler）+ CMS**”三进程方式启动。

1. **启动 API（Cloudflare Worker + D1）**
   - 进入 `cloudflare/` 使用 `wrangler dev` 启动（默认端口建议 `8787`）。
   - 本地默认密钥见 `cloudflare/.dev.vars`。
2. **启动前端（Hugo）**
   - 运行 `hugo server`（默认端口 `1313`）。
3. **启动 CMS（可选，用于编辑 Markdown 内容）**
   - 运行 `netlify-cms-proxy-server --port 8081 --config static/admin/config.yml`。

## 路由与匹配改进
- 统一 `isApi` 去除尾部斜杠并支持子路径匹配，避免路由不命中造成“0 数据”。
- 影响范围：所有 `/api/...` 请求与后台管理接口。

## 数据同步与统计
- 导入接口（需管理员头）：
  - `POST /api/admin/import-news?base=<url>`
  - `POST /api/admin/import-cases?base=<url>`
  - `POST /api/admin/import-products?base=<url>`
- 同步完成后会写入 `system_config.sync_meta`，后台仪表板显示源地址、各模块 upsert 数与更新时间。
- 仪表板统计：`GET /api/admin/stats` 返回新闻、案例、产品、供应商、需求、报价总数与同步信息。

## 产品/新闻/案例 CRUD（ID/slug 双标识）
- 查询详情支持 `product_id` 或 `slug`。
- 更新与删除支持 `product_id` 或 `slug`，减少运维对 ID 的依赖。
- 产品保存使用原子 upsert，避免重复 `slug` 导致失败。

## 需求市场运维
- 前台与后台列表统一过滤：公开状态、审批缺省为通过（`IFNULL(approved, 1) = 1`）。
- 查询参数：
  - `progress`：进度过滤（如 `发布中`、`接洽中`）。
  - `category`：一级分类。
  - `contact_company`：发布公司名。
  - `limit`：返回条数（最大 200）。
- 后台编辑支持新增字段：推荐、紧急、备注、标签、审批时间（`approved_at`）。
- 后台列表统计增加报价数量子查询，便于运维评估活跃度。
- 导出支持 `xlsx`/`csv`（后台按钮已绑定）。

## 供应商运维
- 入口页 `entry-supplier.html`：
  - 登录：`POST /api/suppliers/session`（仅排除 `disabled`）。
  - 注册：`POST /api/suppliers/register`（初始 `pending`，后台启用）。
  - 公司重名检查：`GET /api/suppliers/check-company?name=...`。
- 报价：
  - 提交：`POST /api/quotes`（需传 `supplier_access_password`）。
  - 列表：`GET /api/quotes?requirement_id=...&supplier_id=...&supplier_access_password=...`。
- 后台管理：
  - 列表：`GET /api/admin/suppliers`（支持 `q` 搜索、`limit`/`offset`）。
  - 单条 upsert：`POST /api/admin/suppliers/upsert`（新增或更新）。
  - 更新：`PATCH /api/admin/suppliers/:id`。
  - 删除：`DELETE /api/admin/suppliers/:id`。
  - 导出：`GET /api/admin/suppliers/export`。
- 状态语义：`pending`（待审核）、`active`（启用）、`inactive`（停用）、`disabled`（禁用）。

## 资产（R2）运维
- 列表：`GET /api/admin/assets?limit=20&cursor=...`。
- 上传：`PUT /api/admin/assets?key=<r2_key>`（`Content-Type` 为文件类型）。
- 删除：`DELETE /api/admin/assets?key=<r2_key>`。
- 前台自动生成 `public_url` 供页面引用。

## 操作清单（建议流程）
1. 管理员认证：
   - 浏览器/工具添加 `X-Admin-Key` 请求头。
   - 可选：`POST /api/admin/verify` 携带 `password` 校验环境口令。
2. 内容导入：
   - 按需调用 `admin/import-*` 并确认返回 `upserted`。
   - 在仪表板查看 `sync_meta` 信息与各模块总数。
3. 需求维护：
   - 使用后台编辑审批与公开状态，必要时设置 `approved_at`。
   - 通过过滤参数核对前台与后台一致性。
   - 导出需求数据供审计或外部分享。
4. 供应商维护：
   - 入口页注册并在后台启用（状态改为 `active`）。
   - 用通行密码登录，提交/查看报价。
   - 后台导出 CSV 快速盘点与外部对接。
5. 资产维护：
   - 上传媒体、复制链接、删除无效资源。

## 验证与排错
- 路由不命中：检查路径是否含尾部斜杠，统一使用 `/api/...`。
- CORS 预检失败：确认请求头包含 `X-Admin-Key` 或 `x-admin-key`，且来源允许。
- 保存失败（重复 slug）：确认已启用 upsert，或更换唯一 `slug`。
- 供应商无法登录：确认未设置为 `disabled`；如需仅启用可登录，将会话查询改为 `status='active'`。
- 仪表板“0 数据”：确认导入接口是否成功，`sync_meta` 是否更新。

### 常见线上页面异常（快速定位）
- 案例/资讯缺失页头页脚或样式：优先确认访问的是 `/cases/`、`/news/`（带尾部斜杠的 Hugo 页面），避免命中 `static/cases.html`、`static/news.html` 这类静态兜底页。
